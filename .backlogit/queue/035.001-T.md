## Spike Outcome (2026-06-19): INFEASIBLE -> suppress

Attempted manifest-only bump: indicatif 0.17 -> 0.18 AND hf-hub 0.3 -> 0.4 (resolved indicatif 0.18.4 + hf-hub 0.4.3). Result: number_prefix NOT removed.

- indicatif 0.18 drops number_prefix (replaced by unit-prefix), clearing the direct path.
- hf-hub 0.4.3 STILL pins indicatif ^0.17 -> number_prefix 0.4.0. Both hf-hub API features force `dep:indicatif`: `ureq` (the sync `hf_hub::api::sync::Api` used by src/embed/model.rs) and `tokio` (async). No feature combination yields a usable hf-hub API without indicatif 0.17.
- The hf-hub 0.4 bump also added a large async HTTP cascade (reqwest/tokio/tower/tower-http/hyper/h2/tokio-rustls), exceeding the "cascades unacceptably" guard, and did not remove the advisory.
- Removing number_prefix would require dropping hf-hub or migrating model.rs to the async API plus upstream patching of hf-hub's indicatif pin -- all beyond the 2-file, no-source-change cascade ceiling.

Decision: reverted the manifest experiment (Cargo.toml/Cargo.lock restored to baseline). RUSTSEC-2025-0119 is suppress-only; it joins the four cozo/candle-locked advisories in Unit 2 (035.002-T).
