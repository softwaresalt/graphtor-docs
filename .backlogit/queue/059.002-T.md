Add safe no-follow handle helpers in src/db/store.rs (test-first): open_no_follow(path)->Result<File,GraphtorError> — Unix: OpenOptions .read(true) + custom_flags(libc::O_NOFOLLOW) (O_NOFOLLOW is a modifier that needs an explicit access mode; read access suffices for metadata + fchmod restore and avoids denying an already-read-only file; symlink leaf fails ELOOP -> map to existing refusal error); Windows: custom_flags(FILE_FLAG_OPEN_REPARSE_POINT|FILE_FLAG_BACKUP_SEMANTICS), access_mode(FILE_READ_ATTRIBUTES|FILE_WRITE_ATTRIBUTES), share_mode(FILE_SHARE_READ|FILE_SHARE_WRITE|FILE_SHARE_DELETE). Windows open SUCCEEDS on a reparse point, so the helper MUST then inspect MetadataExt::file_attributes() and refuse via the pure predicate below — fail-closed is an explicit code step on Windows, not a byproduct. Factor the reparse-bit refusal decision into a PURE, TARGET-INDEPENDENT predicate should_refuse_reparse(file_attributes: u32)->bool that tests against a MODULE-PRIVATE literal bit constant const REPARSE_ATTR: u32 = 0x0000_0400 (the numeric value of FILE_ATTRIBUTE_REPARSE_POINT; NOT pub/pub(crate), NOT re-exported, referenced ONLY inside the predicate) — i.e. returns file_attributes & REPARSE_ATTR != 0. should_refuse_reparse is the SINGLE SOURCE OF TRUTH for the reparse-bit decision. The predicate and its literal MUST compile and be unit-tested on Linux CI (no windows-sys, no filesystem, no privilege). The production Windows refusal branch MUST call should_refuse_reparse(file_attributes()) and MUST NOT inline a separate reparse-bit mask or duplicate the literal. To prevent a decorative unused helper OR a duplicated inline mask, acceptance STRUCTURALLY REQUIRES (i) the literal 0x0000_0400/REPARSE_ATTR appears exactly once in the module — inside the predicate — and (ii) a #[cfg(windows)] test drives the production refusal branch through should_refuse_reparse so the helper cannot be dead code. A Windows-only assertion/test (e.g. const_assert or a #[cfg(windows)] #[test]) MUST ALSO prove the literal 0x0000_0400 equals windows_sys::Win32::Storage::FileSystem::FILE_ATTRIBUTE_REPARSE_POINT, so the cross-platform literal can never drift from the real Win32 constant (see U5 delta (f)/(g)). The cap_std::fs::File vs std::fs::File boundary through which open_no_follow returns its handle is PENDING U7 PASS (059.007-T records the exact APIs — either into_std conversion or a capability-file helper signature); it is NOT decided here — U2 carries in whichever boundary U7's recorded evidence selects. Attribute-level access (not GENERIC_WRITE) lets an already-read-only file open without ERROR_ACCESS_DENIED. Also capture_perms(&File)->Result via File::metadata(); set_readonly_via_handle(&File,bool)->Result via File::set_permissions (fchmod / SetFileInformationByHandle), preserving exact perms. No unwrap/expect; all errors map to GraphtorError. Doc-comment: the final-component handle enforces no-follow/no-reparse on the LEAF; FULL-PATH containment is provided by U6 (059.006-T), and the actual bound engine open by U9 (059.009-T). This task DEPENDS ON both and must not be considered complete on its own.
