Add safe no-follow handle helpers in src/db/store.rs (test-first): open_no_follow(path)->Result<File,GraphtorError> — Unix: OpenOptions .read(true) + custom_flags(libc::O_NOFOLLOW) (O_NOFOLLOW is a modifier that needs an explicit access mode; read access suffices for metadata + fchmod restore and avoids denying an already-read-only file; symlink leaf fails ELOOP -> map to existing refusal error); Windows: custom_flags(FILE_FLAG_OPEN_REPARSE_POINT|FILE_FLAG_BACKUP_SEMANTICS), access_mode(FILE_READ_ATTRIBUTES|FILE_WRITE_ATTRIBUTES), share_mode(FILE_SHARE_READ|FILE_SHARE_WRITE|FILE_SHARE_DELETE). Windows open SUCCEEDS on a reparse point, so the helper MUST then inspect MetadataExt::file_attributes() and refuse via the pure predicate below — fail-closed is an explicit code step on Windows, not a byproduct. Factor the reparse-bit refusal decision into a PURE, TARGET-INDEPENDENT predicate should_refuse_reparse(file_attributes: u32)->bool that tests against a MODULE-PRIVATE literal bit constant const REPARSE_ATTR: u32 = 0x0000_0400 (the numeric value of FILE_ATTRIBUTE_REPARSE_POINT; NOT pub/pub(crate), NOT re-exported, referenced ONLY inside the predicate) — i.e. returns file_attributes & REPARSE_ATTR != 0. should_refuse_reparse is the SINGLE SOURCE OF TRUTH for the reparse-bit decision. The predicate and its literal MUST be pure and target-independent so they compile with no windows-sys, no filesystem, and no privilege (this is what lets U11 unit-test the predicate deterministically on Linux CI). The production Windows refusal branch MUST call should_refuse_reparse(file_attributes()) and MUST NOT inline a separate reparse-bit mask or duplicate the literal. U2's IMPLEMENTATION acceptance is limited to building these two properties: (i) the numeric literal 0x0000_0400 appears exactly once in the module — inside the REPARSE_ATTR constant — with every other reference (production branch and any test) using REPARSE_ATTR; and (ii) the production Windows refusal branch calls should_refuse_reparse so the helper is not dead code and no inline mask can diverge from it. The TESTS that PROVE these properties are owned by U11 (059.011-T), NOT by U2, and MUST NOT be treated as U2 completion criteria: (f) the deterministic fabricated-bit predicate unit test on Linux CI; (g1) the #[cfg(windows)] assertion that REPARSE_ATTR equals windows_sys::Win32::Storage::FileSystem::FILE_ATTRIBUTE_REPARSE_POINT (the assertion references REPARSE_ATTR, it does NOT repeat the numeric literal); and (g2) the #[cfg(windows)] structural single-source / production-branch proof. U11 depends on U2 (059.002-T); it does not impose its own tests as U2's completion criteria. The cap_std::fs::File vs std::fs::File boundary through which open_no_follow returns its handle is PENDING U7 PASS (059.007-T records the exact APIs — either into_std conversion or a capability-file helper signature); it is NOT decided here — U2 carries in whichever boundary U7's recorded evidence selects. Attribute-level access (not GENERIC_WRITE) lets an already-read-only file open without ERROR_ACCESS_DENIED. Also capture_perms(&File)->Result via File::metadata(); set_readonly_via_handle(&File,bool)->Result via File::set_permissions (fchmod / SetFileInformationByHandle), preserving exact perms. No unwrap/expect; all errors map to GraphtorError. Doc-comment: the final-component handle enforces no-follow/no-reparse on the LEAF only. U2 provides these leaf primitives, depends solely on U1 (proven deps), and is scheduled BEFORE U6 — it does NOT depend on U6 or U9. FULL-PATH (intermediate-directory) containment is provided by U6 (059.006-T), which COMPOSES these U2 primitives, and the actual bound engine open by U9 (059.009-T) after U6. U2 alone does not close the intermediate-directory race or achieve complete TOCTOU containment; that is completed downstream by U6/U9 (which depend on U2). U2 is complete as the leaf-primitive unit once its own three helper-behavior scenarios pass.
