# Blanket pip auto-approval in .vscode/settings.json (security hardening)

## Problem Frame

<!-- BEGIN:problem-frame -->
.vscode/settings.json chat.tools.terminal.autoApprove contains a blanket "pip": true entry that auto-approves ANY pip command line without operator review, creating an arbitrary-package-install / code-execution path in AI agent sessions (pip runs setup.py at install time). Confirmed pre-existing (predates the 047-S stowaway per git show 33bbb37). Sibling entries are anchored regex patterns with matchCommandLine:true; the bare "pip": true is the outlier that violates least-privilege.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
A) Remove the blanket "pip": true entirely (strongest, smallest diff, no evidence a specific pip command is needed). B) Replace with a narrowly-scoped anchored regex + matchCommandLine:true equivalent to the existing .scripts/*.py patterns (operator recommendation; preserves any reviewed pip workflow). C) Leave as-is (rejected — unmitigated RCE path).
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option B — replace blanket "pip": true with a narrowly-scoped anchored regex (matchCommandLine:true) matching the existing .scripts/*.py convention, with an explicit Option-A fallback to remove the entry entirely if implementation review finds no concrete pip command line is actually required. Classified as a chore (security/config hygiene). Full deliberation artifact: docs/decisions/2026-08-24-vscode-pip-autoapprove-hardening-deliberation.md
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
Does any concrete pip command line need to remain auto-approved (which anchored regex to write), or is outright removal the correct endpoint? Ship implementation/review should confirm against the documented .scripts/*.py clone workflow before finalizing.
