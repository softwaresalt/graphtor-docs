title: JSON-RPC 2.0 output for status and sync commands
updated_at: 2026-05-06T11:31:18.9037023-07:00
---

Update `cmd_status` and `cmd_sync` (both full and incremental) to produce JSON-RPC 2.0 envelopes when the global `--json` flag is set.

For `status`: the existing `StatusArgs.json` flag already produces a JSON object. When the global `--json` flag is set, wrap that JSON in a proper JSON-RPC 2.0 response envelope. The `result` field should contain the same structured status data (chunks, documents, sources, sync state).

For `sync`: the `result` field should report `{ files_processed, chunks_loaded, errors, sources: [...] }` matching the pipeline outcome. Errors during sync should produce a JSON-RPC error envelope with code -32000 (server error) and the error details in `data`.

Acceptance criteria:
- `graphtor-docs status --json` outputs JSON-RPC 2.0 envelope
- `graphtor-docs sync --json` outputs JSON-RPC 2.0 envelope with pipeline stats
- Backward compatibility: `status --json` (subcommand flag) still works standalone
- Unit tests for both JSON-RPC envelopes
- Error paths produce JSON-RPC error envelopes (not raw stderr text)
