File: src/mcp/server.rs

The source_id prefix filter uses String::starts_with() which has an edge-case bug: a filter value of "docs" will incorrectly match paths like "docs-archive/file.md" because the string "docs-archive" starts with "docs".

Required fix:
- After the starts_with() check, verify the match is at a directory boundary: the next character after the prefix must be '/' or the path ends exactly at the prefix
- Suggested pattern: path == prefix || path.starts_with(&format!("{prefix}/"))
- Add unit tests covering: exact match, subdirectory match, false-prefix-match rejection, and empty prefix (matches all)
- Consider a helper function normalize_source_prefix(prefix: &str) -> String that ensures a trailing "/" for consistent matching

This is a correctness bug that can silently return data from unintended sources.
