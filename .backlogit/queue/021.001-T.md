Create comprehensive integration tests covering each acquisition source type end-to-end (acquire → parse → chunk → embed → load). Validate correct handling of edge cases (large files, malformed input, empty documents, nested structures) for each format (PDF, DOCX, Markdown via Git repo). Ensure deterministic chunk IDs and idempotent re-ingestion across all three source types.

<!-- BEGIN:acceptance-criteria -->
1. Integration test for Git source: create a temp git repo with .md + .pdf + .docx files, run full pipeline, verify all formats produce chunks in the store
2. Integration test for Local source: local dir with mixed formats, verify parse + chunk + embed + load for each
3. Integration test for format filtering: source with `formats: ["md"]` skips .pdf and .docx files present in the directory
4. Edge case tests: empty PDF, malformed DOCX, zero-byte files, files with wrong extensions
5. Idempotency test: running the same pipeline twice on the same input produces identical chunk IDs and counts
6. All tests use `tempfile::tempdir()` for isolation, `DataStore::open_mem()` for DB
7. Tests follow TDD (red-green-refactor) per project policy
<!-- END:acceptance-criteria -->

<!-- BEGIN:implementation-notes -->
1. Create test fixtures: minimal valid .pdf (use pdf-extract compatible bytes), minimal valid .docx (use docx-rs to build in-memory), .md files as string literals
2. For Git source tests: use `git2` to init a bare repo in a tempdir, add test files, then run pipeline against it
3. For DOCX: follow the pattern in `pipeline_pdf_test.rs` but create valid DOCX bytes using `docx_rs::Docx::new().add_paragraph(...)` and serialize
4. File: `tests/pipeline_format_test.rs` (new file)
5. Pattern: each test creates its own tempdir, builds a SourceConfig, plans, runs pipeline, asserts PipelineResult fields
6. Edge cases: empty bytes → GraphtorError::Parse, wrong extension → silently skipped
7. Run quality gates: cargo check → clippy → fmt → test
<!-- END:implementation-notes -->
