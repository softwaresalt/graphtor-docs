<!-- BEGIN:implementation-notes -->
OS error 232 (ERROR_NO_DATA) is a write to a closed pipe => server exited before handshake. A nonzero early-exit code settles the diagnosis in one run and may make T3 (model lazy-load) and any rmcp bump unnecessary. See deliberation docs/decisions/2026-08-21-mcp-serve-initialize-os-error-232-deliberation.md. Relevant surfaces: src/main.rs::cmd_serve (~2446-2655), the serve/sync lock entry point is the src/main.rs helper `acquire_database_lock` (~2803-2824), which validates the path and delegates to workspace::lock::DatabaseLock::acquire / handle_existing_lock in src/lock.rs. A genuinely absent default sources.yaml is NOT a fail-closed gate (it falls through to .graphtor/*.db auto-discovery); only a malformed registry or a missing explicit --config exits before serve.
