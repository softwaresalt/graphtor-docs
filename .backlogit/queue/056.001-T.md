<!-- BEGIN:acceptance-criteria -->
- Recorded child exit code and full stderr for the failing launch.
- The launching cwd/env/command line the CLI uses is documented.
- Evidence capture is bounded and owns its child: create `logs/`, keep stdin open, wait at most 30 seconds, record whether the child exited or remained alive, and on timeout terminate only the captured child process handle before collecting stderr. A bare foreground `graphtor-docs serve` command with no timeout is not acceptable evidence.
- Presence/absence of a leftover `.graphtor/*.lock` recorded. If H0b is tested, also record that the fixture/real target resolves to `ServeMode::Generation`; database locks are not acquired for ReadOnly/auto-discovered targets, so a lock file alone is not H0b evidence.
- A named H0 sub-cause (or an explicit H0-ruled-out + H1/H3 pointer) is concluded from the evidence.
- Exact Copilot CLI MCP config schema recorded (F7): `type` vs `transport`, `cwd` support, and `env` handling. The minimal managed contract emits only the evidenced stdio discriminator and `cwd`; env behavior is diagnostic only.
- Client cwd-capability evidence recorded with a backup-first actual-CLI probe: add a temporary isolated entry with a known canonical `cwd`, have its trusted command record the actual cwd, invoke it through the target CLI, then restore the config byte-for-byte. A direct `Command::current_dir` spawn is not client evidence.
- Hosts the H0c workspace-state remediation recipe (056.010-T), manual reinstall fallback (056.009-T), and H3 mode-B client compatibility recipe (056.011-T).
<!-- END:acceptance-criteria -->

<!-- BEGIN:description -->
Investigate-first evidence capture (no production code change). Run the graphtor-docs serve binary with the EXACT command line, working directory, and environment the newest Copilot CLI uses for the child process (from `/mcp show graphtor-docs` and the CLI MCP launch config), with RUST_LOG=debug and stderr redirected to a file. Record the process exit code and stderr; check for a leftover `.graphtor/*.lock`; compare against a prior known-good CLI build if available. Also record the exact Copilot CLI MCP config schema (type vs transport; cwd/env support) for 056.008-T (F7). Determine whether the CLI HONORS `cwd` with the temporary, backup-first real-CLI diagnostic-entry probe in the acceptance criteria; do not infer client behavior from the current managed entry, which has no `cwd`, or from a direct child spawn. Goal: identify which pre-serve early-exit / fail-closed path (H0a cwd-relative discovery / H0b lock contention / H0c fail-closed gate) fires, or rule H0 out and point at H1 latency or an H3 client/transport incompatibility — mode A (child alive, initialize never negotiates) or mode B (the real CLI ignores/rejects the requested cwd).
<!-- END:description -->

<!-- BEGIN:implementation-notes -->
OS error 232 is a write to a closed pipe, so an early nonzero exit is decisive H0 evidence. Use a bounded harness that owns the child handle; on a still-alive timeout record H1/H3-mode-A evidence and stop only that known child. The backup-first cwd probe is operational evidence and must restore the selected MCP config byte-for-byte. For H0b, confirm the source registry classifies the target as Generation before treating a database lock as reachable evidence; ReadOnly/auto-discovered targets do not call `acquire_database_lock`. A genuinely absent default sources.yaml is not a gate; only a malformed registry or missing explicit `--config` exits before serve.
