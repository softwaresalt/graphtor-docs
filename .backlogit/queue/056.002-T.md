<!-- BEGIN:description -->
Add tests/mcp_serve_handshake_test.rs — the common out-of-process transport harness — that spawns the REAL graphtor-docs binary with a controllable working directory and environment, KEEPING the child stdin OPEN, and writes a protocol-valid newline-delimited MCP `initialize` JSON-RPC request (jsonrpc "2.0", method "initialize", an id, params with protocolVersion/capabilities/clientInfo). Its SOLE pass assertion is a successful `initialize` response with a negotiated protocolVersion: RED before the fix (the response never arrives), GREEN after. The reproduced failure is NEVER the expected assertion — on red the harness captures the child exit code + stderr purely as diagnostic evidence explaining the cause (H0: child exited before answering, captured exit/stderr match the T0 marker; H1/H3: child STILL ALIVE but the response misses the bounded deadline / never negotiates). Do NOT use an empty/closed stdin. Pin model-cache state for determinism. Test-first (red) task: no production fix here. This harness is the common red→green proof for the selected curative branch (056.007-T H0b / 056.010-T H0c / 056.005-T H1 / 056.011-T H3); H0a connectivity is proven by 056.008-T's managed-launch integration test (executing the generated contract with pinned cwd) with existing-install delivery in 056.009-T, and the 056.003-T diagnostics task carries its own serve-ready-log/loud-error test.
<!-- END:description -->

<!-- BEGIN:implementation-notes -->
A closed/empty stdin causes a normal EOF-driven shutdown and never writes a real `initialize`, so it cannot reproduce or distinguish the reported client-visible pipe close (OS error 232) — the harness MUST hold stdin open and perform an actual `initialize` write, asserting the SUCCESSFUL response under a bounded timeout (the sole pass condition) while capturing exit/stderr only as diagnostics. An in-process happy-path fixture would negotiate the handshake and pass trivially (rmcp 1.5 negotiates protocolVersion in-SDK), so it must be out-of-process against a fixture workspace that reproduces the T0 sub-cause (e.g. wrong cwd => no databases; or a pre-seeded stale lock). Tie the diagnostic capture to the confirmed T0 marker. Keep existing tests/mcp_manifest_test.rs passing. This is the reusable transport harness; 056.008-T (managed-launch integration test), 056.009-T (migration test), and 056.003-T (serve-ready-log/loud-error diagnostics test) carry their own per-width tests, while the H0b/H0c/H1/H3 curative tasks (056.007/056.010/056.005/056.011) are greened by this harness on their branch. The raw harness cannot green H0a because it controls cwd itself — that is 056.008-T's generated-contract test.
