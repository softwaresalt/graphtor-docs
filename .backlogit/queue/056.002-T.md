<!-- BEGIN:acceptance-criteria -->
- New tests/mcp_serve_handshake_test.rs spawns the real binary out-of-process with a controlled cwd/env and a fixture workspace reproducing the T0 sub-cause.
- The harness keeps the child stdin OPEN, writes a protocol-valid newline-delimited MCP `initialize` JSON-RPC request, and awaits/validates the `initialize` response under a bounded timeout.
- The test is RED for the confirmed T0 cause: the `initialize` write fails on a closed pipe (client-visible OS-error-232 analogue) OR the response never arrives before the deadline because the child exited before answering `initialize`.
- On failure the harness captures the child exit code (or signal) and full stderr and asserts they match the T0 early-exit marker — a red result is tied to the real cause, not to an ambiguous EOF.
- An empty/closed stdin is disallowed (it only exercises a benign EOF-driven shutdown and cannot distinguish the regression).
- Deterministic: model-cache state pinned so the bounded timeout cannot flake on a cold model load.
- Stop gate honored: if the harness cannot be made red for the confirmed T0 cause, halt and return to T0 rather than proceeding.
<!-- END:acceptance-criteria -->

<!-- BEGIN:description -->
Add tests/mcp_serve_handshake_test.rs that spawns the REAL graphtor-docs binary out-of-process with a controllable working directory and environment, KEEPING the child stdin OPEN. Write a protocol-valid, newline-delimited MCP `initialize` JSON-RPC request (jsonrpc "2.0", method "initialize", an id, and params with protocolVersion/capabilities/clientInfo) to the child stdin, then await and validate the `initialize` response under a bounded timeout. Assert the reproduced failure mode: the initialize write fails (broken/closed pipe) or no response arrives before the deadline because the process exits before answering `initialize`; on failure capture the child exit code and full stderr and match them to the T0 early-exit cause. Do NOT use an empty/closed stdin — that only exercises a benign EOF shutdown and cannot distinguish the regression. Pin model-cache state for determinism. This is a test-first (red) task: no production fix here.
<!-- END:description -->

<!-- BEGIN:implementation-notes -->
A closed/empty stdin causes a normal EOF-driven shutdown and never writes a real `initialize`, so it cannot reproduce or distinguish the reported client-visible pipe close (OS error 232) — the harness MUST hold stdin open and perform an actual `initialize` write, validating the response under a bounded timeout. An in-process happy-path fixture would negotiate the handshake and pass trivially (rmcp 1.5 negotiates protocolVersion in-SDK), so it must be out-of-process against a fixture workspace that reproduces the T0 sub-cause (e.g. wrong cwd => no databases; or a pre-seeded stale lock). Capture child exit code + stderr on failure and tie the red assertion to the confirmed T0 marker. Keep existing tests/mcp_manifest_test.rs passing.
