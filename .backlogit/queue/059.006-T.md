Close the intermediate-directory swap race that final-component O_NOFOLLOW / FILE_FLAG_OPEN_REPARSE_POINT alone CANNOT prevent: after validate_path/canonicalization, a workspace writer can still swap an INTERMEDIATE parent directory for a symlink/junction that redirects the final permission mutation outside the workspace. Introduce a containment-safe, directory-identity-bound opener that resolves every guarded target (main db index 0 + -wal/-shm/-journal sidecars) RELATIVE TO A RETAINED WORKSPACE-ROOT DIRECTORY HANDLE so each intermediate component is opened via handle-relative resolution and cannot be redirected post-validation.

GATED ON U7 (059.007-T): this task MUST NOT begin until U7 records a PASS. U7 is the test-first feasibility/evidence gate that proves — with SAFE APIs only, under #![forbid(unsafe_code)] and MSRV 1.75 — the atomic workspace-root directory-handle bootstrap (retained for the DataStore lifetime), the cap_std::fs::Dir/File conversion, the intermediate-swap-refusing component walk, the in-bounds leaf reparse/symlink refusal, and the cap_std::fs::File vs std::fs::File boundary. If U7 returns BLOCKED, U6 stays blocked and Constitution Principles III/IV remain NOT-PASSED.

CANDIDATE DESIGN (cross-platform, safe API — pending the U7 feasibility gate, NOT yet proven): a cap-std capability-based `cap_std::fs::Dir` beneath-root walk. cap-std is the leading candidate for a safe (no in-crate unsafe) capability filesystem that resolves paths component-by-component relative to an open directory handle and is intended to refuse symlink/reparse/`..`/absolute escapes on both platforms (Unix openat/openat2 RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS via the already-transitive rustix 1.1.4; Windows handle-relative NtCreateFile wrapped safely). Whether cap-std actually delivers the exact root/intermediate/leaf semantics we need AND compiles under Rust 1.75 is NOT assumed here — it is the specific claim U7 must PROVE or return BLOCKED. Our crate keeps #![forbid(unsafe_code)] because any unsafe FFI lives inside the dependency.

Mechanics (as U7-proven): open the caller-validated workspace root ONCE as the retained directory-handle authority (bootstrapped per U7 with no-follow/no-reparse semantics from the trusted parent) and convert it to a `cap_std::fs::Dir` (via the File/Dir boundary — PENDING U7 PASS; the exact APIs, into_std conversion or a capability-file helper signature, come from U7's recorded evidence and are NOT decided here). Resolve the db + each sidecar as a path RELATIVE to that Dir. Re-express `open_no_follow(path)` (U2) as `open_beneath(root_dir, relative)` returning an identity-bound handle; retain the existing final-component Windows FILE_ATTRIBUTE_REPARSE_POINT broader fail-closed refusal on the returned handle and the Unix O_NOFOLLOW ELOOP leaf refusal. The same retained root Dir authority is the handle through which U3's transient-sidecar cleanup performs its symlink_metadata/remove_file RELATIVE operations, so an intermediate-directory swap cannot redirect either a permission mutation or a sidecar deletion. Fail CLOSED (traceable GraphtorError) when the root Dir cannot be opened/bootstrapped, any component escapes containment, or the final component is a reparse/symlink. NO unsafe in-crate; NO path-based chmod fallback.

Platform-asymmetry fallback (documented, only reachable if U7 records cap-std BLOCKED under MSRV 1.75): a Unix-only hand-rolled safe rustix openat component walk (OFlags::NOFOLLOW|DIRECTORY per intermediate component, openat2 RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS where the kernel supports it) plus a separately-specified safe Windows design. This fallback is NOT a silent substitute — it too must clear its own feasibility evidence (a follow-on U7-style gate) before adoption; it is never a vague unsafe or path-based fallback. cap-std remains PREFERRED to avoid maintaining two hand-rolled walks. cap-std is added as a direct dependency in U1 (059.001-T, config domain), its feasibility/MSRV proven in U7, and consumed here (code domain) to preserve width isolation.
