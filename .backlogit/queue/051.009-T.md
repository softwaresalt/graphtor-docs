Add managed-entry removal to the MCP config module: uninstall removes the graphtor-managed `.mcp.json` server entry and leaves any user-authored server entries untouched. Match managed entries by (a) the managed-entry PROVENANCE MARKER written at install time (051.004-T / P2-T3) - the primary, forward-looking path - AND (b) a NARROW LEGACY MATCH for entries generated by the CURRENT (pre-marker) writer, which have NO provenance field (PR #88 review comment 3585938909 / thread F). LEGACY MATCH (exact, narrow): the OLD managed shape emitted by managed_server_value (src/workspace/mcp_config.rs:273-279) - command CONTAINS `.graphtor/bin/graphtor-docs` (with or without `.exe`) AND args == [\"serve\"] AND transport == \"stdio\". Uninstall removes/migrates ONLY entries matching the provenance marker OR this exact legacy shape; ALL other unmarked/user entries are preserved. Wire it into uninstall(). Files: src/workspace/mcp_config.rs, src/workspace/uninstall.rs. Depends on P2-T5a (uninstall base) + P2-T3 (marker). Test-first.

<!-- BEGIN:acceptance-criteria -->
uninstall removes a MARKED managed entry (matched by the provenance marker) while a user-authored `.mcp.json` server entry SURVIVES; uninstall ALSO removes an UNMARKED LEGACY entry generated by the current writer (command `.graphtor/bin/graphtor-docs[.exe]`, args ["serve"], transport "stdio", NO provenance marker) so users upgrading directly to this release do not retain a stale registration; a user-authored entry that merely references `.graphtor/bin/graphtor-docs` but does NOT match the exact legacy shape (e.g. different args) is PRESERVED; a `.mcp.json` containing only user entries is left unchanged; the rewrite is atomic (temp-file + rename).
<!-- END:acceptance-criteria -->

<!-- BEGIN:implementation-notes -->
Provenance marker is written by the shared writer (051.004-T) on BOTH the minimal and full install paths. Removal matches by marker OR the narrow legacy shape - never by key name alone - so a user-authored entry with a similar name (or an incidental `.graphtor/bin/graphtor-docs` occurrence in a differently-shaped entry) is preserved. Backward-compat (PR #88 comment 3585938909 / thread F): entries generated by the current writer have no provenance field and are identified only by the `.graphtor/bin/graphtor-docs` command + serve args + stdio transport (src/workspace/mcp_config.rs:29-36,225-231,273-279); a marker-only removal would strand them as stale MCP registrations. The legacy match is deliberately NARROW (command marker AND exact serve args AND stdio transport) to avoid removing a user entry that merely references the binary path. Executed by Ship (part of PA-3); Stage plans only.
