Add managed-entry removal to the MCP config module: uninstall removes the graphtor-managed `.mcp.json` server entry and leaves any user-authored server entries untouched. Match managed entries by (a) the managed-entry PROVENANCE MARKER written at install time (051.004-T / P2-T3) - the primary, forward-looking path - AND (b) a NARROW LEGACY MATCH for entries generated by the CURRENT (pre-marker) writer, which have NO provenance field (PR #88 review comments 3588876275 / 3588876318, original thread F / comment 3585938909). LEGACY MATCH (EXACT equality): the OLD managed shape emitted by managed_server_value (src/workspace/mcp_config.rs:273-279) - command EQUALS the normalized value `.graphtor/bin/graphtor-docs` OR `.graphtor/bin/graphtor-docs.exe` (exact string equality AFTER path normalization; NEVER a CONTAINS/substring test) AND args == ["serve"] AND transport == "stdio". Uninstall removes/migrates ONLY entries matching the provenance marker OR this exact legacy shape; ALL other unmarked/user entries are preserved. Wire it into uninstall(). Files: src/workspace/mcp_config.rs, src/workspace/uninstall.rs. Depends on P2-T5a (uninstall base) + P2-T3 (marker). Test-first.

<!-- BEGIN:acceptance-criteria -->
uninstall removes a MARKED managed entry (matched by the provenance marker) while a user-authored `.mcp.json` server entry SURVIVES; uninstall ALSO removes an UNMARKED LEGACY entry generated by the current writer whose command EQUALS `.graphtor/bin/graphtor-docs` or `.graphtor/bin/graphtor-docs.exe` (exact), args == ["serve"], transport "stdio", NO provenance marker, so users upgrading directly to this release do not retain a stale registration; a user-authored command with an EXTRA PREFIX OR SUFFIX around the legacy path (e.g. `/opt/tools/.graphtor/bin/graphtor-docs`, or `.graphtor/bin/graphtor-docs-wrapper`) SURVIVES even when its args are ["serve"] and transport is "stdio" (exact-equality match, NOT CONTAINS); a user-authored entry that references the pinned command but with DIFFERENT args is PRESERVED; a `.mcp.json` containing only user entries is left unchanged; the rewrite is atomic (temp-file + rename).
<!-- END:acceptance-criteria -->

<!-- BEGIN:implementation-notes -->
Provenance marker is written by the shared writer (051.004-T) on BOTH the minimal and full install paths. Removal matches by marker OR the narrow legacy shape - never by key name alone - so a user-authored entry with a similar name (or a differently-shaped entry that merely embeds `.graphtor/bin/graphtor-docs`) is preserved. Backward-compat (PR #88 comments 3588876275 / 3588876318, original thread F / comment 3585938909): entries generated by the current writer have no provenance field and are identified ONLY by EXACT normalized command equality to `.graphtor/bin/graphtor-docs` or `.graphtor/bin/graphtor-docs.exe` + serve args + stdio transport (src/workspace/mcp_config.rs:29-36,225-231,273-279); a marker-only removal would strand them as stale MCP registrations. The legacy match MUST be exact string equality (after path normalization), NOT a CONTAINS/substring test - CONTAINS could delete an unmarked user command that embeds the legacy path as a prefix/suffix but is otherwise the user's own (this is the SAME exact-equality predicate as P2-T3 / 051.004-T case-3 migration). Add a prefixed/suffixed-command preservation test. The legacy match stays deliberately NARROW (exact command equality AND exact serve args AND stdio transport). Executed by Ship (part of PA-3); Stage plans only.
