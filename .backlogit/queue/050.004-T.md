In serve_discovery, classify each candidate db into a per-db ServeMode with a THREE-WAY outcome that runs BEFORE the write-path run_duplicate_intake_preflight (src/main.rs:2398-2406). Expose a PURE function returning BOTH the Vec<(PathBuf, ServeMode)> classification AND the filtered per-database Generation source groups (the subset of source groups whose resolved target db is Generation), so downstream preflight/background sync receive ONLY Generation sources and never the full SourceConfig. Depends on P1-T1. Test-first.

<!-- BEGIN:acceptance-criteria -->
(1) malformed/unparseable sources.yaml -> fail-closed hard Err(GraphtorError); (2) a local source whose path exists AND has >=1 ingestible file promotes ONLY the candidate db whose resolved (canonicalized) path equals that source's resolved target db -> Generation; a resolvable source NEVER promotes an unrelated co-resident dropped db (stays ReadOnly); (3) absent/empty/stale/unresolvable sources -> ReadOnly. The function ALSO returns filtered Generation-only source groups; a MIXED config (valid source -> db A, stale/unresolvable source -> db B) yields a Generation group for ONLY db A while db B is ReadOnly and excluded. Tests: real non-empty source->Generation; existing-but-empty path->ReadOnly; stale sources.yaml paths absent->ReadOnly; malformed yaml->hard error; source-backed db + co-resident dropped db -> only the source's target db is Generation; mixed valid+stale sources targeting DIFFERENT dbs -> only the valid db's source group is returned.
<!-- END:acceptance-criteria -->

<!-- BEGIN:implementation-notes -->
Change cmd_serve call ordering so classification precedes the preflight. 'Resolvable real source' = path exists AND >=1 ingestible file (locked stricter definition per decision doc). Returning filtered Generation source groups (not the full SourceConfig) is what lets P1-T3 hand ONLY Generation sources to run_duplicate_intake_preflight and spawn_background_sync, which internally re-splits its SourceConfig via split_plan_by_database (src/main.rs:2268-2269) - a full config would otherwise re-schedule stale/read-only targets.
