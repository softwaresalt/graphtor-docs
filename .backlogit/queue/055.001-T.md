Reduce source_has_ingestible_content (src/workspace/serve_discovery.rs:333) memory without changing semantics. Keep iterating the ENTIRE WalkDir and keep returning false on any walk error (fail-closed, unchanged). Replace the relative_candidates Vec + single batch filter_files call with a streaming boolean using a SHARED reusable matcher (the same compiled include/exclude matcher filter_files uses) - do NOT call filter_files per file (that recompiles glob sets per entry and emits a per-file 'all files excluded' warning). Because the classifier is in the graphtor-docs BINARY crate and the matcher/filter_files are in the graphtor_core LIBRARY crate, this shared predicate MUST be exposed as an ADDITIVE public API in graphtor_core::acquire (e.g. a FileFilter type with new/is_match), with filter_files refactored to consume it (single source of truth; additive, SemVer-minor, no breaking change; no forked glob logic). Return found only when the walk completed without error. This removes O(document-count) memory; the full traversal is retained deliberately to preserve fail-closed. A traversal short-circuit (return true on first eligible file) is REJECTED: it would skip later walk errors and escalate a partially-unreadable read-only source to the read-WRITE Generation posture. Source: B88E37BF.

1) Full error-observing walk retained; false on any WalkDir error. 2) No per-file Vec; memory no longer scales with document count. 3) Classification identical to before (differential test vs old filter_files(&all)-then-non-empty over nested paths, multi-segment/union include globs, empty include, exclude-wins). 4) Regression test: an eligible file encountered BEFORE an unreadable subtree returns false - driven through an injected ordered walk-result seam (WalkDir order is unspecified). 5) Aggregate 'all files excluded' warning parity is exact and testable: (a) an excluded-only tree (format-matching candidates existed, none passed) emits exactly one aggregate warning, matching the old batch filter_files call; (b) an ingestible source (>=1 candidate passes) emits zero warnings; (c) a walk error emits no misleading warning (fail closed to false, no aggregate 'all excluded' message); (d) a zero-candidate tree (no format-matching files at all) emits no misleading aggregate 'all files excluded' warning; no per-file warnings in any case. 6) cargo test + clippy pedantic green. 7) The shared matcher is exposed as an additive public API in graphtor_core::acquire (crate boundary: classifier in the graphtor-docs binary, matcher in the graphtor_core library) with /// rustdoc and a colocated library-crate unit test; filter_files is refactored to consume it (additive, SemVer-minor, no breaking change).
