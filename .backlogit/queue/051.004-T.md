Make the MCP config writer (generate_mcp_config / managed_server_value, src/workspace/mcp_config.rs:84-140) the shared foundation both install paths consume. It provides: (a) a binary-resolution LADDER - reference the pinned absolute .graphtor/bin/graphtor-docs (+ platform ext) when a managed binary exists, otherwise the bare graphtor-docs PATH command (no .exe; Windows resolves via PATHEXT); (b) a managed-entry PROVENANCE MARKER written into the server entry so uninstall (P2-T5b) can identify the graphtor-managed entry; (c) ATOMIC temp-file + rename writes with stable key ordering (Principle IX); and (d) a LOCKED fixed-key collision contract for the `graphtor-docs` key in `.mcp.json`. LOCKED collision behavior (PR #88 review comment 3585938864 / thread E) - the current writer does `servers.insert(\"graphtor-docs\", ...)` (src/workspace/mcp_config.rs:131-134), which overwrites an unmarked user entry using that exact key; replace it with a three-way, provenance-marker-keyed decision on the `graphtor-docs` key: (1) ABSENT -> insert a new managed entry (with the provenance marker) atomically; (2) PRESENT AND carrying the graphtor provenance marker (managed) -> UPDATE it atomically in place (refresh command/args/marker via the resolution ladder); (3) PRESENT but WITHOUT the provenance marker (user-authored/unmarked) -> FAIL CLOSED: do NOT overwrite - return a GraphtorError::Config collision error and leave the user's .mcp.json byte-for-byte unchanged. This is the Phase-2 root. Files: src/workspace/mcp_config.rs (+ a shared atomic-write helper if extracted). Depends on Phase 1 (050-F). Test-first.

<!-- BEGIN:acceptance-criteria -->
resolution ladder unit-tested as a pure function - managed binary present -> pinned .graphtor/bin/graphtor-docs + platform ext; no managed binary -> bare graphtor-docs PATH command with NO .exe; every written managed server entry contains the managed-entry provenance marker; the write is atomic (temp-file + rename) with stable key ordering.

LOCKED fixed-key collision contract (exact tests for the `graphtor-docs` key):
- `.mcp.json` with NO `graphtor-docs` key -> a marked managed entry is created; any other (user) servers are preserved;
- `.mcp.json` with an EXISTING graphtor-managed `graphtor-docs` entry (has the provenance marker) -> the entry is UPDATED atomically in place (marker retained); user servers preserved;
- `.mcp.json` with an UNMARKED user-authored `graphtor-docs` key (e.g. { "command": "my-graphtor", "args": [...] }, no marker) -> installation FAILS CLOSED with a collision error and the user's entry is preserved BYTE-FOR-BYTE (no overwrite);
- a pre-existing `.mcp.json` with unrelated user servers is preserved (only the managed entry is written/updated).
<!-- END:acceptance-criteria -->

<!-- BEGIN:implementation-notes -->
Phase-2 root (thread 7): binary resolution + provenance marker + atomic write must exist BEFORE minimal install (P2-T1) claims a working install. The current writer hardcodes .graphtor/bin/... (mcp_config.rs:86) and always creates it; this task replaces that with the ladder + marker + atomic write + LOCKED collision contract. Fixed-key collision (PR #88 comment 3585938864): fail-closed on an unmarked user `graphtor-docs` key is chosen over silent overwrite because it is enforceable-by-test and consistent with the module's existing non-clobbering posture (it already refuses to clobber invalid-JSON files at mcp_config.rs:110-113 and preserves shared configs on remove). The provenance marker (a dedicated key in the server entry, e.g. an x-graphtor-managed marker) is the single source of truth for 'managed'; the legacy command-marker path (`.graphtor/bin/graphtor-docs`) is handled by P2-T5b (051.009-T) for backward-compatible removal. Both the minimal (P2-T1) and full (P2-T2b) paths consume this writer, guaranteeing marker parity for uninstall (P2-T5b). Bare-PATH fallback carries a documented binary-hijack trade-off; prefer the absolute pinned path when known.
