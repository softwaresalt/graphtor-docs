P1-RF4 (Source-variant compatibility pre-refactor 4 of 5). Refactor EVERY irrefutable/non-exhaustive `Source::Local` consumer in src/main.rs (the v4-migration + sync/prewarm command surface) so they are variant-safe BEFORE the `type: database` variant lands — this is the largest external file, with NINE production consumers. Production sites: `source_id` (~L655), `changed_source_fields` (~L661), `guard_no_embed_before_v4_rebuild` epoch-mismatch match (~L1280), `collect_candidate_md_files` (~L1310), `collect_snapshot_candidates` match (~L1410), `freeze_v4_migration_input` match (~L1486), `run_incremental_sync` match (~L2070), `cmd_prewarm` match (~L3382), and `prewarm_sync_source` match (~L3435). Also route the ONE colocated `#[cfg(test)]` binding (~L4323, the persisted-v4-snapshot retry test) through `as_local()` so main.rs's own tests stay green. Route id-only sites through the existing `Source::id()` accessor and the rest through `Source::as_local()` (P1-RF1 / 050.010-T); while only `Local` exists behaviour is identical, so this task is independently green. This task ALSO gates the GENERATION db-discovery/splitting against non-ingestible sources with TWO separate, accurately-scoped guards (the two functions iterate DIFFERENT collections): (i) `discover_db_files` (~L244) iterates `source_config.sources` (~L247), so gate THAT loop on `as_local()`; and (ii) `split_plan_by_database` (~L273) SEEDS its db-keyed map from the now-filtered `discover_db_files` (~L279) but then iterates `plan.sources` (~L284-290), where `plans_by_db.entry(db_path).or_insert_with(...)` (~L286-288) could re-introduce a db key for a non-local planned source, so gate THAT `plan.sources` loop on `as_local()` too. The split-side guard is belt-and-suspenders on top of RF2's (050.011-T) filtered `AcquisitionPlan` invariant, which already excludes `Database` from `plan.sources`. So a non-ingestible `Database` source is EXCLUDED from generation discovery AND splitting and is never opened read-write (PR #88 threads PRRT_kwDORiB5E86RNyT4 / PRRT_kwDORiB5E86RO5GB). This is a SHRINKING exclusion filter (it can only REMOVE a non-ingestible source from the generation set), so it PRESERVES the P0-1 invariant that the sync/write set must never be ENLARGED and is distinct from the P1-T1 constraint that forbids feeding auto-discovered root-scan dbs BACK into `discover_db_files`/`split_plan_by_database`. NO new variant is added here (that is P1-T6). Files: src/main.rs (1 file). Depends on 050.012-T (P1-RF3). Test-first.

<!-- BEGIN:implementation-notes -->
Uniform mechanical accessor-routing across ONE file/domain: each site replaces an irrefutable `let Source::Local(...)` or single-arm `match` with a centralized accessor call, so despite the site count this stays width-isolated (one skill: variant-safe refactor) with <=3 test-scenario families (the <5-functions heuristic targets distinct logic changes, not uniform mechanical refactors).
Id-only sites — `source_id` (~L655) and the six `... => local.id...` match arms (`guard_no_embed_before_v4_rebuild` ~L1280, `collect_snapshot_candidates` ~L1410, `freeze_v4_migration_input` ~L1486, `run_incremental_sync` ~L2070, `cmd_prewarm` ~L3382, `prewarm_sync_source` ~L3435) — delegate to the existing `Source::id()` accessor (its match is centralized in source.rs), so adding the variant only touches source.rs. Because src/main.rs is the BIN crate (a SEPARATE crate from the library), it reaches `Source::id()` and `Source::as_local()` as the now-public accessors from P1-RF1 (050.010-T), which declares `as_local()` `pub` and widens `id()` from `pub(crate)` to `pub`; without that widening these bin-crate call sites would not compile.
`changed_source_fields` (~L661): replace `let (Source::Local(current), Source::Local(persisted)) = (current, persisted);` with `as_local()` on both operands, returning an empty/defensive changed-field set when either is non-local — a served db is not part of the v4 generation snapshot.
`collect_candidate_md_files` (~L1310): replace `let Source::Local(local) = &planned.source;` with `as_local()` to read id/include/exclude for the scan; a served db is skipped from the v4 migration candidate scan by design.
Colocated test (~L4323, persisted-v4-snapshot retry): route `let Source::Local(local) = &persisted.sources[0].source;` through `as_local()`. The four `source: Source::Local(LocalSource { .. })` CONSTRUCTORS in main.rs tests (~L3672/L3729/L3894/L4027) are non-breaking and untouched.
Generation discovery/splitting filter — TWO separate guards, because the two functions iterate DIFFERENT collections: (i) `discover_db_files` (~L244) iterates `source_config.sources` (~L247), so gate that loop on `as_local()` (e.g. `if source.as_local().is_none() { continue; }`); (ii) `split_plan_by_database` (~L273) SEEDS its `plans_by_db` keys from the now-filtered `discover_db_files` (~L279) but then iterates `plan.sources` (~L284-290), and `plans_by_db.entry(db_path).or_insert_with(...)` (~L286-288) can RE-INTRODUCE a db key for a non-local planned source, so gate that `plan.sources` loop on `as_local()` too (skip a non-local `planned.source` before `resolve_source_db_path`/`or_insert_with`). This split-side guard is belt-and-suspenders on top of RF2 (050.011-T), whose filtered `AcquisitionPlan` already excludes `Database` from `plan.sources` before this function runs (RF2 acceptance: a mixed local/database config plans ONLY the local source); the explicit guard means the exclusion still holds even if that upstream invariant regressed, and while only `Local` exists all sources pass at BOTH sites (independently green). So a `Database` source contributes no generation target and is never grouped for a read-write open. Because `database()` stays local-target-only (returns `None` for `Database`; 050.006-T), the filter is the explicit non-ingestible exclusion the reviewer requires "before generation discovery/splitting"; while only `Local` exists all sources pass, so the enumerated db set is identical (independently green). This SHRINKS (never enlarges) the generation set, preserving the P0-1 invariant. Add a filter test asserting a `Database` source is dropped from the generation set — covering BOTH the `discover_db_files` seed path and the `split_plan_by_database` `plan.sources`/`or_insert_with` re-introduction path — once the variant lands. The filter must skip a `Database` source ENTIRELY so it contributes no db candidate (it must NOT fall through `resolve_source_db_path`'s `database()==None` default to `base_db_path`, which would otherwise route the served entry toward the default graph.db). For a database-ONLY config the filtered iteration leaves `discover_db_files` empty: its existing empty-set fallback to `base_db_path` (src/main.rs:251-253) and the `graph.db` write-fallback are owned by P1-T3 (zero-discovered-db handling / `unreachable!` removal) and such a consumption-only workspace is classified read-only by P1-T2 (content-derived mode), so RF4's filter must NOT itself fabricate or open a writable `base_db_path`; the served `type: database` entry reaches the serve candidate union via the P1-T6 merge (P1-T1), NOT via `discover_db_files`.
While only `Local` exists behaviour is identical. This closes the LAST src/main.rs consumer; only the EXTERNAL integration tests (P1-RF5 / 050.014-T) remain before the additive variant in 050.006-T. Pure structural refactor; gates P1-T6. Executed by Ship; Stage plans only.
