Support an explicit read-only database entry via a NEW, DISTINCT `type: database` source variant (NOT a `read_only: true` flag on the local source — the distinct variant avoids overloading ingestion-only LocalSource fields and is the safest additive change). The `Source` enum is already an internally-tagged serde enum (`#[serde(tag = "type", rename_all = "lowercase")]`, src/config/source.rs:51-56) with only `Local(LocalSource)` today; adding `Database(DatabaseSource)` yields `type: database` in YAML — existing `type: local` entries parse unchanged and unknown types (git/url) stay rejected. The change is additive at the serde/parse level AND compile-safe for consumers because the Source-variant compatibility pre-refactors P1-RF1..P1-RF4 (050.010-T -> 050.011-T -> 050.012-T -> 050.013-T) already routed EVERY external irrefutable `Source::Local` binding (config validation, acquire/plan, acquire/mod, pipeline/mod, sync/mod, main.rs) through variant-safe accessors — see PR #88 review comments 3588876057 / 3588876095. LOCKED serialized contract (see Acceptance): DatabaseSource has exactly two REQUIRED fields — `id: String` (unique alias/name) and `path: PathBuf` (workspace-contained) — and no other fields in Phase 1 (the variant is inherently read-only; there is NO `read_only` field). Each `DatabaseSource.path` is canonicalized and validated via validate_path (src/path/security.rs:143) to stay within the SAME authorized root as auto-discovery; out-of-root/external paths (`..`, POSIX symlink, Windows junction/reparse) are REJECTED, not served — external-path support is explicitly OUT of Phase-1 scope (do NOT broaden authorized roots). Explicit entries merge through serve_discovery with CANONICAL-path dedup against auto-discovery (an explicit entry whose canonical path equals an auto-discovered db collapses to one store; the explicit entry's `id` supplies the served alias/name). This task LOCKS mixed local+database behaviour through BOTH `serve` (the database entry is served read-only) AND `sync` (the database entry is ignored — acquisition/sync already filter non-ingestible sources by design via the P1-RF1..P1-RF4 `as_local()` / `is_ingestible()` gates, so `cmd_sync` / main.rs is NOT touched here and P1-T6 stays at 2 source files). Depends on P1-T3 (050.001-T) AND the pre-refactor chain tail P1-RF4 (050.013-T). Test-first.
