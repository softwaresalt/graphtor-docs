Support an explicit read-only database entry via a NEW, DISTINCT `type: database` source variant (NOT a `read_only: true` flag on the local source — the distinct variant avoids overloading ingestion-only LocalSource fields and is the safest additive change). The `Source` enum is already an internally-tagged serde enum (`#[serde(tag = "type", rename_all = "lowercase")]`, src/config/source.rs:51-56) with only `Local(LocalSource)` today; adding `Database(DatabaseSource)` yields `type: database` in YAML and is purely additive — existing `type: local` entries parse unchanged and unknown types (git/url) stay rejected. LOCKED serialized contract (see Acceptance): DatabaseSource has exactly two REQUIRED fields — `id: String` (unique alias/name) and `path: PathBuf` (workspace-contained) — and no other fields in Phase 1 (the variant is inherently read-only; there is NO `read_only` field). Each `DatabaseSource.path` is canonicalized and validated via validate_path (src/path/security.rs:143) to stay within the SAME authorized root as auto-discovery; out-of-root/external paths (`..`, POSIX symlink, Windows junction/reparse) are REJECTED, not served — external-path support is explicitly OUT of Phase-1 scope (do NOT broaden authorized roots). Explicit entries merge through serve_discovery with CANONICAL-path dedup against auto-discovery (an explicit entry whose canonical path equals an auto-discovered db collapses to one store; the explicit entry's `id` supplies the served alias/name). Depends on P1-T3. Test-first.

<!-- BEGIN:acceptance-criteria -->
LOCKED YAML contract + fixture (add to the acceptance fixture set):

```yaml
sources:
  - type: database
    id: rust-stdlib          # required: unique alias/name for the served db
    path: rust-stdlib.db     # required: workspace-contained path to the pre-built .db
```

Required fields: `type: database`, `id` (unique alias/name), `path` (workspace-contained). Optional fields: NONE in Phase 1 (the variant IS read-only; a `read_only` field is intentionally absent). `id` is the served alias/name and MUST be unique across sources.

Scenarios:
- an explicit `type: database` entry is served read-only + never synced;
- an explicit entry + auto-discovery for the SAME file collapse to one store (canonical-path dedup; the explicit entry's `id` is the served alias/name);
- an explicit `type: database` entry whose `path` uses `..` traversal, a POSIX symlink, a Windows junction/reparse point, or any path resolving OUTSIDE the authorized root is REJECTED with a path-violation error (served set unchanged; authorized roots NOT broadened);
- a pre-change `sources.yaml` (only `type: local` entries) round-trips unchanged (backward-compat parse), and the LOCKED `type: database` fixture above parses to `Source::Database(DatabaseSource { id, path })`.
<!-- END:acceptance-criteria -->

YAML contract LOCKED (PR #88 review comment 3585938805 / thread 5): the ambiguity between `read_only: true` on a local source and a `type: database` kind is resolved in favour of the DISTINCT additive variant `type: database` — it does not overload LocalSource's ingestion-only fields (include/exclude/formats/database) and keeps validation semantics clean. Serde: add `Database(DatabaseSource)` to the existing internally-tagged `Source` enum (src/config/source.rs:51-56); the two DatabaseSource fields (id, path) are REQUIRED so no `#[serde(default)]` is needed. LocalSource is UNTOUCHED, so every existing `sources.yaml` round-trips with zero risk and the original deny_unknown_fields concern is moot (no fields are added to LocalSource); DatabaseSource follows the existing convention (no deny_unknown_fields set on the enum today). Update the `Source` accessor match arms (id/formats/include/exclude/database) for the new variant: a `Database` source has no ingestion formats/include/exclude (return empty) and is never handed to the ingestion/generation path — serve_discovery classifies it ReadOnly. Path containment reuses validate_path (src/path/security.rs:143), the same guard DataStore::open_sqlite/open_sqlite_readonly already applies (src/db/store.rs:117-118). NOTE the orthogonality: LocalSource.database (a generation TARGET filename) is unrelated to the `type: database` VARIANT (a pre-built read-only served db). Add the pre-change round-trip parse test plus traversal/symlink/junction/outside-root rejection tests.
