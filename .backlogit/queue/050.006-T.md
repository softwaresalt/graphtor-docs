Support an explicit read-only database entry (e.g. read_only: true or a type: database kind) for NAMED/ALIASED dbs, merged through serve_discovery with CANONICAL-path dedup against auto-discovery. Phase-1 explicit entries MUST remain workspace-contained: each entry's path is canonicalized and validated to stay within the same authorized root as auto-discovery (validate_path, src/path/security.rs:143). Out-of-root/external paths are REJECTED, not served - external-path support is explicitly OUT of Phase-1 scope (do not broaden authorized roots). SourceConfig schema change MUST be additive. Depends on P1-T3. Test-first.

<!-- BEGIN:acceptance-criteria -->
explicit workspace-contained read-only entry served read-only + never synced; explicit entry + auto-discovery for the same file collapse to one store (canonical-path dedup); an explicit entry whose path uses `..` traversal, a POSIX symlink, a Windows junction/reparse point, or any path resolving OUTSIDE the authorized root is REJECTED with a path-violation error (served set unchanged); a pre-change sources.yaml round-trips (backward-compat parse).
<!-- END:acceptance-criteria -->

<!-- BEGIN:implementation-notes -->
Use #[serde(default)] on new fields; check for deny_unknown_fields so existing dev-workspace sources.yaml still deserializes. Every DataStore open already validates the db path against the workspace root and rejects outside paths (src/db/store.rs:117-118 -> validate_path, src/path/security.rs:143), so 'external' entries cannot be served without broadening authorized roots - out of scope here. Add a pre-change round-trip parse test plus traversal/symlink/junction/outside-root rejection tests.
