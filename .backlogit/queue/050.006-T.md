Support an explicit read-only database entry via a NEW, DISTINCT `type: database` source variant (NOT a `read_only: true` flag on the local source — the distinct variant avoids overloading ingestion-only LocalSource fields and is the safest additive change). The `Source` enum is already an internally-tagged serde enum (`#[serde(tag = "type", rename_all = "lowercase")]`, src/config/source.rs:51-56) with only `Local(LocalSource)` today; adding `Database(DatabaseSource)` yields `type: database` in YAML — existing `type: local` entries parse unchanged and unknown types (git/url) stay rejected. The change is additive at the serde/parse level AND compile-safe for consumers because the Source-variant compatibility pre-refactors P1-RF1..P1-RF5 (050.010-T -> 050.011-T -> 050.012-T -> 050.013-T -> 050.014-T) already routed EVERY irrefutable/non-exhaustive `Source::Local` consumer — all 18 production sites (config validation, acquire/plan, acquire/mod, pipeline/mod, sync/mod, main.rs) AND every breaking test consumer (src/config/source.rs + src/main.rs colocated tests, plus external tests/config_test.rs & tests/pipeline_format_test.rs) — through variant-safe accessors, so both `cargo build` AND `cargo test` stay green — see PR #88 review comments 3588876057 / 3588876095. LOCKED serialized contract (see Acceptance criteria): DatabaseSource has exactly two REQUIRED fields — `id: String` (unique alias/name) and `path: PathBuf` (workspace-contained) — and no other fields in Phase 1 (the variant is inherently read-only; there is NO `read_only` field). Each `DatabaseSource.path` is canonicalized and validated via validate_path (src/path/security.rs:143) to stay within the SAME authorized root as auto-discovery; out-of-root/external paths (`..`, POSIX symlink, Windows junction/reparse) are REJECTED, not served — external-path support is explicitly OUT of Phase-1 scope (do NOT broaden authorized roots). Explicit entries merge through serve_discovery with CANONICAL-path dedup against auto-discovery (an explicit entry whose canonical path equals an auto-discovered db collapses to one store; the explicit entry's `id` supplies the served alias/name). This task LOCKS mixed local+database behaviour through `serve` (the database entry is served read-only), `sync` (the database entry is ignored), AND `generation` (the database entry is EXCLUDED from `discover_db_files`/`split_plan_by_database`, never opened read-write): acquisition, sync, AND generation db-discovery/splitting already filter non-ingestible sources by design via the P1-RF1..P1-RF4 `as_local()` / `is_ingestible()` gates — P1-RF2 (050.011-T) gates the acquisition plan loop, P1-RF3 (050.012-T) gates the per-source sync path, and P1-RF4 (050.013-T) gates the GENERATION discovery/splitting path — so `cmd_sync` / main.rs is NOT touched here and P1-T6 stays at 2 source files. Depends on P1-T3 (050.001-T) AND the pre-refactor chain tail P1-RF5 (050.014-T). Test-first.

Three high-level verification scenarios (all substantive checks retained):

(a) serde shape + round-trip (happy path / backward-compat) — the LOCKED `type: database` contract holds: `DatabaseSource` serializes/parses with EXACTLY two REQUIRED fields `id: String` (unique alias/name) and `path: PathBuf`, and NO other fields (no `read_only` field); a `type: database` entry round-trips through the internally-tagged `Source` enum; every existing `type: local` entry parses UNCHANGED (LocalSource backward compatibility — zero `sources.yaml` regression) and unknown types (`git`/`url`) stay rejected.

(b) containment / fail-closed rejection — each `DatabaseSource.path` is canonicalized and validated via validate_path (src/path/security.rs:143) to stay within the SAME authorized root as auto-discovery; `..` traversal, POSIX symlink, and Windows junction/reparse paths that escape the canonical root are REJECTED (not served); external-path support is explicitly OUT of Phase-1 scope (authorized roots are NOT broadened).

(c) canonical merge + mixed serve/sync + green build (compatibility) — canonical-path dedup collapses an explicit entry whose canonical path equals an auto-discovered db into ONE served store, with the explicit entry's `id` supplying the served alias/name; a MIXED local+database workspace serves the database entry read-only through `serve` (via the distinct `served_db_path` accessor) AND, through `sync`, still syncs the local source while the database entry is ignored, AND, through generation, EXCLUDES the database entry from `discover_db_files`/`split_plan_by_database` so it is never opened read-write (per the P1-RF1..P1-RF4 `as_local()` / `is_ingestible()` gates, with P1-RF4 gating the generation discovery/splitting path); `database()` stays local-target-only (returns `None` for `Database`); compile + clippy-pedantic AND `cargo test --all-targets` stay GREEN after the pre-refactors (all 18 production and every breaking test consumer were routed through `Source::id()` / `as_local()` / `is_ingestible()` first), with the variant addition touching only the src/config/source.rs match arms (2 implementation files: src/config/source.rs + src/workspace/serve_discovery.rs).

<!-- BEGIN:implementation-notes -->
YAML contract LOCKED (PR #88 review comment 3585938805 / thread 5): the ambiguity between `read_only: true` on a local source and a `type: database` kind is resolved in favour of the DISTINCT additive variant `type: database` — it does not overload LocalSource's ingestion-only fields (include/exclude/formats/database) and keeps validation semantics clean. Serde: add `Database(DatabaseSource)` to the existing internally-tagged `Source` enum (src/config/source.rs:51-56); the two DatabaseSource fields (id, path) are REQUIRED so no `#[serde(default)]` is needed. LocalSource is UNTOUCHED, so every existing `sources.yaml` round-trips with zero risk and the original deny_unknown_fields concern is moot (no fields are added to LocalSource); DatabaseSource follows the existing convention (no deny_unknown_fields set on the enum today). Update the `Source` accessor match arms for the new variant: `id()` returns the required `DatabaseSource.id` alias (the served store name/alias — NOT empty); `formats()`/`include()`/`exclude()` return empty (a `Database` source has no ingestion globs/formats); `database()` STAYS local-target-only and returns `None` for the `Database` variant — it MUST NOT return the served path (PR #88 thread PRRT_kwDORiB5E86RNyT4). `database()` feeds the ingestion/generation WRITE path: config validation rejects path separators (src/config/validation.rs:82-105), `resolve_source_db_path` joins the returned name under the base-db parent (src/config/validation.rs:336-344), and `discover_db_files`/`split_plan_by_database` open each resulting group read-WRITE via `with_locked_database_store` (src/main.rs:244-293,481-496); reusing it for a prebuilt read-only path would either reject a valid contained path or route the served db into the write/sync path. Instead add a DISTINCT database-variant accessor `served_db_path(&self) -> Option<&Path>` (returns `Some(&DatabaseSource.path)` for `Database`, `None` for `Local`) that serve_discovery consumes for the read-only served path. `as_local()` returns `None` and `is_ingestible()` returns `false`, so a `Database` source is never handed to the ingestion/generation path — serve_discovery classifies it ReadOnly. Path containment reuses validate_path (src/path/security.rs:143), the same guard DataStore::open_sqlite/open_sqlite_readonly already applies (src/db/store.rs:117-118). NOTE the orthogonality: LocalSource.database (a generation TARGET filename, exposed by `database()`) is unrelated to the `type: database` VARIANT (a pre-built read-only served db, exposed by `served_db_path()`). Add the pre-change round-trip parse test plus traversal/symlink/junction/outside-root rejection tests.

External-consumer compile safety (PR #88 comments 3588876057 / 3588876095; fourth-pass exact-count audit): every irrefutable/non-exhaustive `Source::Local` consumer — all 18 production sites AND every breaking test binding — was already routed through `Source::as_local()` / `Source::id()` / `is_ingestible()` by the pre-refactors P1-RF1 (050.010-T: accessors + config validation `validate`/`detect_with_context`/`intake_key` + src/config/source.rs colocated tests), P1-RF2 (050.011-T: acquire/plan + acquire/mod), P1-RF3 (050.012-T: pipeline/mod + sync/mod), P1-RF4 (050.013-T: all nine src/main.rs production sites + its colocated test), and P1-RF5 (050.014-T: external tests/config_test.rs + tests/pipeline_format_test.rs). Therefore adding the variant here only extends the src/config/source.rs match arms (as_local -> None, is_ingestible -> false, id -> the required `DatabaseSource.id` alias, formats/include/exclude -> empty, database -> `None` [local-target-only; NOT the served path], plus the new `served_db_path` accessor -> `Some(DatabaseSource.path)`); no source OR test file outside src/config/source.rs needs a compile fix, which the mixed-config build + clippy-pedantic + `cargo test` gate confirms.

Ingestion AND generation filtering is owned by the pre-refactors, NOT this task: P1-RF2 (050.011-T) gates the acquisition consumers (including the plan loop), P1-RF3 (050.012-T) gates the per-source sync path, and P1-RF4 (050.013-T) gates the GENERATION db-discovery/splitting path (`discover_db_files` / `split_plan_by_database`), all on `as_local()` / `is_ingestible()`, so a `Database` entry is excluded from acquisition, sync, AND generation write BY DESIGN and this task does NOT touch `cmd_sync` / main.rs (keeping P1-T6 at 2 source files: src/config/source.rs + src/workspace/serve_discovery.rs). This task's mixed local+database `sync` integration test LOCKS that no database entry is ingested while the local source still syncs; the mixed generation test LOCKS that a `Database` entry is EXCLUDED from `discover_db_files`/`split_plan_by_database` (never opened read-write); the mixed `serve` test locks that the database entry is served read-only via `served_db_path`. Test files are separate from the source-file budget. Executed by Ship; Stage plans only.
