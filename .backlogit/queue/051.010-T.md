upgrade() of a consumption (minimal, no-bin) install treats missing bin/subdirs as a no-op success rather than an error; a full install upgrade replaces the copied binary as today. This is now purely ADDITIVE: because P2-T1 PRESERVES the full-scaffold install(), the existing full-install upgrade path (and its tests) stay green throughout - this task only ADDS the minimal (no-bin) no-op case. Idempotent across both footprints. Files: src/workspace/upgrade.rs (+ src/main.rs cmd_upgrade if wiring is needed). Depends on P2-T1 (minimal install) + P2-T2b (full scaffold). Test-first.

<!-- BEGIN:acceptance-criteria -->
upgrade of a minimal (no-bin) install succeeds as a no-op (no error, no bin created); upgrade of a full install replaces the binary (existing behaviour, still green); re-running upgrade is idempotent for both footprints.
<!-- END:acceptance-criteria -->

<!-- BEGIN:implementation-notes -->
Reuse the footprint-detection helper shared with install/uninstall where practical (INV-6). Missing bin/subdirs on a minimal layout are expected, not a failure. Because P2-T1 preserves install() (backward-compat design, PR #88 review comment 3585938838 / thread 8-followon), no upgrade regression exists between P2-T1 and this task - the minimal no-op case is purely additive, not a deferred fix for a broken upgrade.
