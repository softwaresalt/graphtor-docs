Bounded, TEST-FIRST feasibility/evidence gate that MUST prove — using SAFE APIs ONLY — that the selected capability-based beneath-root containment design is actually achievable under #![forbid(unsafe_code)] and MSRV 1.75 BEFORE U6 (059.006-T) builds on it. This unit exists to remove the prior overclaim that cap-std is already known to deliver the exact root/intermediate/leaf containment semantics and Rust-1.75 compatibility; nothing downstream may assume it until U7 records a PASS. GATES U6 (059.006-T depends on U7) and therefore transitively U2/U3/U4/U5.

Author the evidence tests/harness FIRST (observed failing/absent), then the minimal proof code, proving ALL of the following with safe APIs only:

1. Atomic workspace-root directory-handle bootstrap with no-follow/no-reparse semantics via SAFE std OpenOptions, retained for the DataStore lifetime:
   - Unix: OpenOptions with read access + custom_flags(O_DIRECTORY | O_NOFOLLOW); if the root itself is a symlink the bootstrap fails closed.
   - Windows: OpenOptions directory handle with custom_flags(FILE_FLAG_BACKUP_SEMANTICS | FILE_FLAG_OPEN_REPARSE_POINT), explicit access_mode (at least FILE_READ_ATTRIBUTES) and share_mode (FILE_SHARE_READ|WRITE|DELETE), then an explicit post-open FILE_ATTRIBUTE_REPARSE_POINT attribute REJECTION of the root.
   - THREAT MODEL (state explicitly in the evidence): an attacker may create/write/swap entries INSIDE the workspace root, but NOT its trusted parent; the root handle is bootstrapped once from the trusted parent and retained, so the root identity cannot be redirected post-bootstrap.
2. Conversion to/from cap_std::fs::Dir / cap_std::fs::File (e.g. Dir::from_std_file, File into/from std) — or whichever safe capability API is selected — proven to round-trip the retained root handle into the capability authority with NO in-crate unsafe.
3. A component walk that PREVENTS escape (.., absolute, out-of-root) AND REFUSES an INTERMEDIATE symlink/junction swap of a parent directory (the delta that final-component O_NOFOLLOW/OPEN_REPARSE_POINT cannot cover).
4. A final, IN-BOUNDS leaf symlink/reparse is REFUSED (fail-closed), not merely prevented from escaping — an in-root leaf link is still rejected.
5. The cap-std candidate COMPILES under Rust 1.75 (cargo +1.75.0 check / rustup run 1.75.0 cargo check on the feasibility harness) AND the cap_std::fs::File vs std::fs::File BOUNDARY is decided and PROVEN here as U7's deliverable: either the into_std conversion path or explicit capability-file helper signatures, with the exact chosen APIs RECORDED on PASS. The boundary is PENDING U7 PASS — it remains undecided until U7 records PASS; on PASS the recorded evidence is what U6/U2 carry in.

OUTCOME CONTRACT: if every obligation is proven -> PASS: record the evidence (API names, pinned versions, test results, chosen File boundary) in the plan/PR and UNBLOCK U6. If ANY required API/semantic fails under the safe-API / MSRV-1.75 constraints -> U7 returns BLOCKED to Stage: record the specific failing obligation, keep U6/U2-U5 gated, and Constitution Principles III/IV remain NOT-PASSED. NO vague unsafe and NO path-based chmod/re-canonicalization fallback is an acceptable substitute for the proof.
