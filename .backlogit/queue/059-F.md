Eliminate two sibling check-then-use TOCTOU symlink/reparse swap vulnerabilities on the read-only permission mutation paths in src/db/store.rs by binding every permission operation to an identity-bound, no-follow file handle instead of re-resolving paths. Covers BOTH EngineReadonlyGuard lock/acquisition-rollback/Drop restore (main db index 0 + all sidecars) and clear_stale_readonly_lock write-mode sidecar permission probe/clear. Fail-closed on any link/reparse/unobtainable handle; NO path-based chmod fallback. Preserves exact-permission restoration and sidecar-content invariants. Consumes stash E86A6E56 (clear_stale_readonly_lock, high) and 5905CDEE (EngineReadonlyGuard, medium).

## PR #107 review addendum (2026-08-25)

Honest status correction from the PR #107 Copilot review remediation:

- **Intermediate-directory threat**: final-component O_NOFOLLOW / FILE_FLAG_OPEN_REPARSE_POINT does NOT prevent a post-`validate_path` swap of an INTERMEDIATE parent directory redirecting the mutation outside the workspace. This is closed by U6 (059.006-T) resolving every component relative to a retained workspace-root directory handle.
- **U7 feasibility gate (059.007-T, NEW)**: the cap-std beneath-root design is a CANDIDATE, not proven. U7 is a bounded, test-first evidence gate that must PROVE (safe APIs only, MSRV 1.75) the root-handle bootstrap (with an explicit threat model: attacker may write inside the workspace root but not its trusted parent), the cap_std Dir/File conversion and File-vs-std boundary, the intermediate-swap-refusing component walk, and the in-bounds leaf reparse/symlink refusal — or return BLOCKED. U7 gates U6, which gates U2-U5.
- **Engine-open boundary**: U7 must also prove that `configure_sqlite_wal` and `open_sqlite_instance`/`DbInstance::new` remain capability- or identity-bound. Passing `safe_path` back to a path-only engine API after guarded preparation leaves the intermediate-swap race open and forces U7 to return BLOCKED.
- **Transient cleanup identity**: root-relative `symlink_metadata` followed by `remove_file` is still a check/use race at the final name. U3 now fails closed by retaining transient sidecars unless a safe same-identity deletion API is proven.
- **Deterministic predicate**: the Windows reparse refusal is a pure target-independent should_refuse_reparse predicate over the literal 0x0000_0400, unit-tested on Linux CI, with a #[cfg(windows)] assertion pinning the literal to windows-sys FILE_ATTRIBUTE_REPARSE_POINT.
- **Honest Principles III/IV status**: NOT-PASSED / provisional until U7 records PASS and U6 lands. The prior "essentially complete" framing on final-component no-follow alone is withdrawn.
