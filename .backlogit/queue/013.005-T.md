File: Cargo.toml

tokio = { features = ["full"] } pulls in all tokio subsystems including timers, fs, process, net, signal, and test utilities. The MCP server over STDIO only requires a subset.

Steps:
1. Audit actual tokio API surface used in src/ (grep for tokio:: imports)
2. Replace "full" with the minimal feature set. Based on STDIO MCP usage the expected set is:
   - rt-multi-thread (multi-threaded async runtime)
   - macros (#[tokio::main], tokio::select!)
   - io-util (AsyncRead/AsyncWrite for STDIO)
   - sync (Mutex, RwLock, channels if used)
3. Run cargo check and cargo test to confirm nothing regresses
4. Document the chosen feature set in a comment above the tokio dependency entry

This reduces compile time and binary size. The "full" feature is appropriate for development/prototyping but not for a production dependency.
