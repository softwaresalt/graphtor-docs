Change EngineReadonlyGuard to retain the opened File for each guarded entry (guarded: Vec<GuardedEntry { file: File, path: PathBuf, original: fs::Permissions }>). lock opens every existing entry INCLUDING index 0 (main db) via open_no_follow, captures original perms via the handle, applies read-only via the handle, and on any mid-loop error rolls back already-locked entries through their retained handles. Drop restores exact perms via each retained handle. Delete the in-loop is_reparse_point re-check (superseded: a successful open_no_follow, incl. the Windows reparse-attribute refusal from U2, proves the entry is not a followed link). Each fail-closed refusal returns a structured traceable GraphtorError (Principle V), never a silent early return. Transient sidecars (-wal/-shm/-journal the ENGINE, not the guard, creates) have no retained identity-bound handle at Drop. A directory-relative symlink_metadata-then-remove_file sequence is still a check/use race: a writer can replace the observed empty entry with a non-empty live sidecar before unlink. Therefore the default safe behavior is to LEAVE transient sidecars in place unless this unit proves a safe API that binds the emptiness observation and deletion to the same file identity. Root-relative containment alone is insufficient. No separate metadata-check + name-based unlink is allowed; inability to prove identity-bound deletion fails closed by retaining the sidecar. Consumes stash 5905CDEE.
