Change EngineReadonlyGuard to retain the opened File for each guarded entry (guarded: Vec<GuardedEntry { file: File, path: PathBuf, original: fs::Permissions }>). lock opens every existing entry INCLUDING index 0 (main db) via open_no_follow, captures original perms via the handle, applies read-only via the handle, and on any mid-loop error rolls back already-locked entries through their retained handles. Drop restores exact perms via each retained handle. Delete the in-loop is_reparse_point re-check (superseded: a successful open_no_follow, incl. the Windows reparse-attribute refusal from U2, proves the entry is not a followed link). Each fail-closed refusal returns a structured traceable GraphtorError (Principle V), never a silent early return. Transient sidecars (-wal/-shm/-journal the ENGINE, not the guard, creates) have no per-entry retained no-follow handle at Drop, but their empty-only cleanup MUST still be performed RELATIVE TO THE RETAINED WORKSPACE-ROOT CAPABILITY DIRECTORY HANDLE (the U6 root Dir authority): probe emptiness via a directory-handle-relative symlink_metadata and unlink via a directory-handle-relative remove_file, so an intermediate-directory swap between the emptiness probe and the unlink cannot redirect the deletion outside the workspace. A planted link is still not removed as a target (relative symlink_metadata reports the link; relative remove_file unlinks the link itself, never its target). This is fully contained through the root Dir handle — do NOT describe or accept it as a path-based residual. Consumes stash 5905CDEE.
