title: Implement `manifest` subcommand emitting JSON-RPC 2.0 tool list
updated_at: 2026-05-06T11:31:18.4036208-07:00
---

Add a `Manifest` variant to the `Command` enum in `src/cli/mod.rs` and implement `cmd_manifest()` in `src/main.rs`. The command emits a JSON-RPC 2.0 response whose `result` field mirrors the MCP `tools/list` response — an array of tool definitions with `name`, `description`, and `inputSchema` (JSON Schema for parameters).

The tool list should include entries for all CLI-accessible commands that produce queryable output: `search_local_docs`, `traverse_doc_links`, `search_semantic`, `research_topic`, `list_sources`, `get_chunk_by_id`, `get_document`, `get_status`. The manifest must be generated from the same source of truth as the MCP server (i.e., derive from the same type metadata or a shared registry).

When `--json` is NOT set, print a human-readable table of tool names and descriptions instead.

Acceptance criteria:
- `graphtor-docs manifest` prints the tool list in JSON-RPC 2.0 format (when --json)
- Tool names, descriptions, and inputSchema match what the MCP server reports via tools/list
- Human-readable table output when --json is absent
- Tool definitions derived from a shared source (not duplicated strings)
- Integration test comparing manifest output to MCP tool_router metadata
