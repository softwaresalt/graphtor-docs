        Chore: reduce CI build actions to only run on code changes, to conserve GitHub Actions usage limits.

        IDEA: The CI workflow (.github/workflows/ci.yml) currently runs the full build/fmt/clippy/test/audit pipeline on every PR/push, including chore/docs-only PRs where compilation is unnecessary. Skip the heavy build actions where they add no value.

        APPROACHES TO CONSIDER:
        - paths-ignore: on the workflow triggers to skip runs when only non-code paths change (e.g. docs/**, **/*.md, .github/agents/**, .github/instructions/**, .github/prompts/**).
        - PR-title-based conditional gating on jobs/steps, e.g.:
            if: |
              !startsWith(github.event.pull_request.title, 'chore:') &&
              !startsWith(github.event.pull_request.title, 'docs:')
          to skip build actions for chore:/docs: PRs.
        - Or a combination of path filters + title-based skip.

        GOAL: Only run heavy build/clippy/test/audit actions when code actually changes, reducing GitHub Actions minutes/usage.

        CAVEATS TO ADDRESS DURING DESIGN:
        - Required status checks + branch protection: if the build check is a REQUIRED check, skipping the job (job never runs) can BLOCK merge because the required check never reports a conclusion. Options: use workflow-level paths/paths-ignore filters (GitHub treats path-skipped required checks as passing) rather than per-job if:; or add a companion job that reports success on skip; or make the check non-required. Design must not deadlock merges of chore/docs PRs.
        - push to main should still run full CI (or at least on release-relevant changes).
        - Keep the audit gate running whenever Cargo.lock / Cargo.toml change (advisory gate) even for chore/docs PRs.
        - Title-based gating is fragile (PR title can change after checks run) and spoofable; path-based filtering is more robust — weigh both.

        TOUCH POINTS: .github/workflows/ci.yml (triggers, job-level if / paths-ignore).
