title: Integrate Format Filtering into Pipeline Dispatch
updated_at: 2026-05-02T11:59:47.5890414-07:00
---

Modify the pipeline dispatch in `src/pipeline/mod.rs` to consult each source's `formats` field before processing a file. Files whose extension does not match the source's declared formats should be skipped (not counted as errors). This adds a source-level gating layer on top of the existing extension-based parser dispatch.

<!-- BEGIN:acceptance-criteria -->
1. Pipeline skips files whose extension is not in the source's `formats` list
2. Skipped-by-format files are logged at DEBUG level, not counted as errors
3. A source with `formats: ["md", "pdf"]` processes .md and .pdf, skips .docx
4. A source with default formats (omitted field) processes only .md files
5. Existing pipeline tests pass unchanged (backward compatibility)
6. Pipeline result struct includes a `skipped_by_format` count for observability
<!-- END:acceptance-criteria -->

<!-- BEGIN:implementation-notes -->
1. The `formats` field is available on the `Source` enum variants; extract it via a helper `Source::formats() -> &[String]`
2. Add a `fn is_format_allowed(extension: &str, formats: &[String]) -> bool` helper
3. In the pipeline's per-file processing loop, check format allowance before extension dispatch
4. Add a `skipped_by_format: usize` field to `PipelineResult`
5. TDD: write a test that asserts .pdf files are skipped when formats is ["md"]
6. Files touched: `src/pipeline/mod.rs`, `src/config/source.rs` (add `formats()` accessor)
7. Run quality gates after each change
<!-- END:implementation-notes -->
