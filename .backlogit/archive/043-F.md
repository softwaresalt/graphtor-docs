        Cross-source cross-product link resolution in graph traversal.

        PROBLEM: doc_edges { src_chunk_id, target_path => link_text, anchor } (src/db/edges.rs) stores link targets as raw strings. find_related_chunks (src/db/traverse.rs) resolves each target_path only against doc_chunks where source_id = seed.source_id AND path == target_path — deliberately source-scoped. So cross-product links (absolute Learn URL paths like /fabric/admin, and any link whose target lives in a different ingested source) never resolve; a multi-source DB is fragmented at source boundaries for graph traversal. (Vector search in src/db/search.rs is already cross-source; this is graph-edge-only.)

        GOAL: Let traversal follow an edge whose target is a document in a different source when a reliable, globally-unique key identifies that target — without reintroducing the relative-path ambiguity the current source-scoping prevents.

        CROSS-SOURCE KEY (contract with docline): Introduce a canonical_url identifier per chunk/doc, populated from a new docline frontmatter field canonical_url (the Learn URL a doc publishes under, e.g. /fabric/admin/foo, forward-slash, no host). Index it as a new relation, e.g. doc_url_index { canonical_url: String => source_id: String, chunk_id: String } (or a canonical_url column on doc_chunks plus a lookup). canonical_url MUST be globally unique across sources.

        TWO-TIER RESOLUTION (in chunks_at_path / a new resolver): Tier 1 (unchanged): intra-source exact match — source_id = seed.source_id AND path == target_path. Keeps within-repo relative links fast and preserves the source-pollution guard. Tier 2 (new): if target_path is absolute (starts_with('/')) or Tier 1 returns nothing, look up doc_url_index by canonical_url == target_path — not source-scoped — resolving to (target_source_id, target_chunk_id).

        TRAVERSAL CHANGES (find_related_chunks): after Tier-1, for unresolved/absolute targets call the new global chunk_by_canonical_url(target_path); enqueue the resolved chunk with its own source_id so subsequent hops are scoped correctly to the doc's home source. Respect max_depth. Unresolved target stays a dangling edge (no crash, no false match).

        EDGE TYPING (recommended): classify each edge as intra_source vs cross_product (absolute target, or resolved to a different source_id) so consumers can weight/filter cross-repo hops.

        ACCEPTANCE: (1) Two sources (e.g. powerbi + fabric) in one DB: a /fabric/admin/foo link from a powerbi chunk resolves via find_related_chunks to the fabric chunk (different source_id) when a matching canonical_url exists. (2) Intra-source relative links resolve exactly as before — no regression; identical relative source_paths across sources are NOT cross-linked. (3) Cross-product links with no matching canonical_url remain dangling (graceful). (4) Traversal hops across sources up to max_depth; anchors on cross-product edges are preserved.

        OUT OF SCOPE: Deriving canonical_url (docline owns that). Changing vector search. Rewriting stored link text.

        TOUCH POINTS: src/db/schema.rs (new relation/column + migration), src/db/edges.rs (index population), src/db/traverse.rs (chunks_at_path, find_related_chunks), src/parse/frontmatter.rs (read canonical_url if keying off frontmatter), src/db/chunks.rs (carry canonical_url).
