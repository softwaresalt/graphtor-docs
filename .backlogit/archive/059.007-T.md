Scenario 2 (CORRECTED root bootstrap): the originally-recorded bootstrap, Dir::open_ambient_dir(root, ambient_authority()) alone, does NOT provide a no-follow/no-reparse root bootstrap -- it follows a symlinked root (verified empirically in an earlier pass: the symlink was followed and a file read straight through it). CORRECTED construction (this is what the 6/6-passing harness above actually exercises): open the workspace root's PARENT ambiently -- cap_primitives::fs::open_ambient_dir(parent, ambient_authority()) -- then open the root ITSELF relative to that parent handle via cap_primitives::fs::open_dir_nofollow(&parent_std_file, root_name), which refuses if the root is a symlink/reparse point (open_dir_nofollow is pub fn in cap-primitives 4.0.3's fs::open_dir module, re-exported via pub use open_dir::* in cap-primitives::fs, but is NOT exposed as a cap_std::fs::Dir method -- it must be called via a direct cap-primitives dependency, then the resulting std::fs::File wrapped via cap_std::fs::Dir::from_std_file). Refusal signal observed: ERROR_STOPPED_ON_SYMLINK/os error 681 on Windows; ENOTDIR/os error 20 on Linux (the cap-primitives/kernel combination reports ENOTDIR rather than ELOOP for this open shape; the open still FAILS and the symlink is never followed either way). The trusted-parent threat model is now precise: ONLY the immediate parent of the workspace root is trusted (the same single ambient-authority step any std::fs ambient call already makes); the root itself is no-follow-verified by actual execution on both platforms under both toolchains. File boundary DECIDED (unchanged): cap_std::fs::File::into_std() -> std::fs::File. IMPLEMENTATION NOTE for U1/U2/U6: both cap-std (Dir/File capability-relative walk) AND cap-primitives (open_dir_nofollow root-bootstrap primitive) must be adopted as direct dependencies -- cap-std alone is insufficient.

Scenario 3 (NOW cross-platform executed against the corrected handle): a table-driven capability-walk refusal matrix, exercised through open_beneath on the SAME bootstrap_root_nofollow-produced Dir as Scenario 2, refuses in all 6/6-passing runs on both platforms: (a) absolute path, (b) ".." escape, (c) intermediate-directory symlink swap, (d) in-bounds leaf symlink.
