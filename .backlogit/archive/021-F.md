Mature the documentation source registry (sources.yaml) to support mixed-format ingestion per source: each Git, URL, or local source entry should declare which document types it contains (PDF, DOCX, Markdown) so the pipeline dispatches the correct parser per file. Add schema validation, default format lists, and per-source format override configuration. This enables a single Git repo source to ingest its Markdown, PDF, and DOCX files in one pass.

<!-- BEGIN:dod -->
1. `formats` field present on GitSource, LocalSource, and UrlSource with serde defaults
2. Config validation rejects unknown format values (accepted: md, pdf, docx)
3. Pipeline skips files whose extension does not match the source's declared formats
4. All existing tests pass without modification (backward compatibility)
5. Integration tests cover each format × source-type combination end-to-end
6. All quality gates pass: cargo check → clippy pedantic → fmt check → cargo test
<!-- END:dod -->

<!-- BEGIN:goals -->
1. Each source entry in sources.yaml can declare which document formats it contains
2. Pipeline dispatches the correct parser per file based on source-level format declarations
3. Schema validation rejects unknown format strings
4. Backward-compatible: omitting `formats` defaults to `["md"]`
5. Single Git repo source can ingest its Markdown, PDF, and DOCX files in one pass
<!-- END:goals -->
