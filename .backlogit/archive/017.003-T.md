Add four new MCP tools to `DocServer` in `src/mcp/server.rs` following the established pattern (param struct → #[tool] macro → validation → DB call → format → CallToolResult::success):

1. `list_sources` — No required params. Calls `db::nodes::list_sources`, formats with `format_sources_list`. Description must guide agents: "List all indexed documentation sources with their IDs, names, types, and last sync timestamps."

2. `get_chunk_by_id` — Param: `chunk_id: String`. Calls `db::chunks::get_chunk`. Returns formatted chunk detail on success. Returns `invalid_params` for empty chunk_id. Returns descriptive "chunk not found" content (not error) when None — follows same convention as search returning "No results."

3. `get_document` — Params: `path: String`, `source_id: Option<String>`, `limit: Option<u32>` (default 50, max 200). Calls `list_chunks_by_path`, optionally filters by source_id, applies limit, formats with `format_document_chunks`. Returns `invalid_params` for empty path.

4. `get_status` — No required params. Calls `DataStore::get_status`, formats with `format_status`. Description: "Get database health and statistics — relation counts, schema version, and storage backend info."

Tests (test-first, using existing test_server() helper):
- list_sources on empty store returns success with "No sources" message
- get_chunk_by_id with empty string returns invalid_params
- get_chunk_by_id with unknown ID returns success with "not found" content
- get_document with empty path returns invalid_params
- get_status returns success with counts
