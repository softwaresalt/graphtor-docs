## Description

Add an end-to-end integration test for `parse_pdf_document` using a real
public-domain PDF binary as a test fixture. The current unit tests mock
`OutputDev` directly, which validates the state machine in isolation but
cannot catch regressions in how `pdf_extract::output_doc()` actually emits
words, lines, and pages.

## Acceptance Criteria

- Select a small (< 100KB) public-domain PDF with varied font sizes (e.g.
  a multi-heading academic abstract or a cover page with title/body text)
- Commit the PDF as `tests/fixtures/sample_heading.pdf`
- Write an integration test `parse_pdf_heading_aware_real_pdf` that:
  - Calls `parse_pdf_document(bytes, "sample_heading.pdf")`
  - Asserts result is `Ok`
  - Asserts at least 2 chunks are produced
  - Asserts at least one chunk has a non-empty `heading_hierarchy`
- Run the test in CI without any conditional skip
