Improve graphtor-docs console output so failures and degraded modes are clear and actionable in an interactive terminal.

Two threads:
(1) Friendly fatal-error rendering with the full cause chain, actionable hints, and TTY colour (already implemented via src/cli/errfmt.rs).
(2) Make a missing/unloadable embedding model loud — render the embed diagnostic in TTY red and surface a prominent end-of-sync warning when embeddings were skipped, so sync no longer silently degrades to a graph/keyword-only index (origin: a real user could not tell embeddings were skipped).

Acceptance criteria:
- Fatal errors print `error:` + `Caused by:` chain + optional `hint:` with bold-red/cyan labels on a TTY; ANSI stripped on non-TTY and when NO_COLOR is set.
- `--json` errors carry a structured `data` payload (category, cause_chain, hint).
- When the embedding model cannot be found/loaded, the `[embed] ... unavailable` diagnostic header is rendered in bold red on a TTY.
- After a sync where embeddings were skipped (model unavailable, not --no-embed), a prominent coloured warning states that semantic search is unavailable and chunks were stored without vectors.
- Non-TTY/piped output is plain; NO_COLOR respected. Existing tests pass; new pure formatter helpers are unit-tested.

Implementation notes:
- errfmt lives in the bin crate (src/cli/errfmt.rs) using anstream::AutoStream + anstyle.
- Embed diagnostics live in the lib crate (src/embed/resolver.rs: emit_resolution_diagnostic, emit_local_dir_diagnostic) — add anstream/anstyle colouring there (both are now direct deps).
- End-of-sync warning: in cmd_sync, when the resolved model is None and not --no-embed, emit a coloured WARN summary before emit_sync_output.
