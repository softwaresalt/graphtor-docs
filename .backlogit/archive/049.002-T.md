        Console UX: when the embedding model directory cannot be found/loaded, print the diagnostic to the console in TTY red so the user clearly understands the model was missing (and that sync therefore degraded to graph-only with no vector embeddings).

        Context / root cause: src/embed/resolver.rs emits the "[embed] local embedding model unavailable" / "[embed] embedding model unavailable" diagnostics via plain uncolored eprintln! (emit_local_dir_diagnostic ~L215-231, emit_resolution_diagnostic ~L193-210). On load failure resolve_embedding_model() degrades to Ok(None) and sync continues WITHOUT embeddings (doc_chunks.embedding stays null), which silently produces a graph/keyword-only index. A real user hit this and did not realize embeddings were skipped.

        Desired behavior:
        - Render the missing/unloadable embedding-model diagnostic in bold red on a TTY (auto-detected, honoring NO_COLOR), consistent with the new src/cli/errfmt.rs anstream/anstyle color approach (AutoStream strips ANSI on non-TTY). Note: the diagnostic lives in the graphtor-core lib (embed module), while errfmt is in the bin crate — either move a small shared color helper into the lib or add anstream/anstyle usage in the embed module.
        - Also make the degraded outcome prominent at end of sync (e.g., a colored WARN summary line like "embeddings skipped — semantic search unavailable; N chunks stored without vectors") so the skip is not easily missed among logs.

        Acceptance: on a TTY with a missing GRAPHTOR_EMBED_MODEL_DIR (or absent model files), sync prints a clearly red warning that embeddings were skipped; piped/non-TTY output is plain (NO_COLOR respected); existing tests still pass. Related to the error-messaging color work (errfmt) shipped for the fatal-error path.
